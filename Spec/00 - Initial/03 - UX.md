# UX — Screens, Flows & Copy

Every screen, every state, and the exact words. Copy in this document is the spec, not a
suggestion: the difference between a usable personal tool and an annoying one is almost
entirely in what the error states say.

Design language: Material 3, dynamic colour, dark theme first-class. One frame (D6), so
there is no frame picker anywhere in v1.

---

## 1. Navigation graph

```
                    ┌─────────────────┐
  cold start ──────▶│ Home            │◀──────── share sheet (already paired)
                    │ (frame card)    │
                    └────┬───┬───┬────┘
                         │   │   │
        Add photos ──────┘   │   └────── Gallery ──▶ Photo preview
             │               │              ▲
             ▼               │              └── Request photo access (if not granted)
       System picker         │
             │               └────── Settings ──▶ Diagnostics
             ▼                                └──▶ Connection details
      Review & Send ──▶ (queue) ──▶ Home / back to sharing app

  no pairing yet:
  cold start / share ──▶ Connect frame ──▶ Find frame ──▶ Friend code ──▶ Home
```

## 2. Connect frame (first run)

Shown whenever no pairing exists.

**Empty state**

> ### Connect your frame
> FrameAlt sends photos straight to your Frameo frame over Wi-Fi. No account, no
> subscription, no limit on how many photos you send at once.
>
> **Before you start**, on the frame: open the menu, choose **Add friend**, and leave
> the code on screen.
>
> [ Find my frame ]
> [ Enter an address instead ]

Requirements listed inline, not behind a link: phone and frame on the same Wi-Fi; the
frame powered on and awake.

### 2.1 Find frame

Runs mDNS discovery for 5 s with a spinner, then lists results.

- Each row: a friendly label and the address. The instance name is a 63-char hex blob
  and must **never** be shown raw — render `Frame at 192.168.1.42` plus, in a secondary
  line, `ID 5c2a3eea…`. The real name only becomes known after connecting.
- While scanning: "Looking for frames on <SSID>…"
- Found none:
  > **No frames found.** Check that the frame is on and connected to <SSID>. Some
  > routers block device discovery — you can enter the frame's address by hand instead.
  >
  > The frame's address is on the frame under Settings → About.
  >
  > [ Scan again ]  [ Enter an address ]

### 2.2 Manual address entry

Two fields, `Host or IP` and `Port`. Validate: non-empty host, port 1–65535. No default
port is assumed — the frame advertises its own and it is not a fixed well-known value,
so the field is required and the hint points at the frame's About screen.

### 2.3 Friend code & sender name

> ### Enter the friend code
> On the frame, choose **Add friend**. Type the code it shows.
>
> [ 1234 5678 90 ]  ← digits only, spaces and dashes ignored, 7–20 digits
>
> **Your name on the frame**
> [ Dmitrii ]  ← ≤ 100 characters, pre-filled with the phone's owner name if available
>
> [ Connect ]

Inline validation: "Friend codes are 7 to 20 digits." / "Friend codes contain digits
only." Do not disable the button before the user has typed — validate on submit.

### 2.4 Pairing progress and outcomes

Progress: "Connecting to the frame…" → "Verifying the code…". Whole flow has a 30 s
ceiling.

| Outcome | Message |
|---|---|
| Success | "Connected to **<frame name>**." → Home |
| Wrong/expired code | "That code didn't work. Codes expire — open **Add friend** on the frame again and use the new code." |
| Frame unreachable | "Couldn't reach the frame. Make sure it's on and connected to <SSID>, then try again." |
| Identity mismatch vs discovery | "This frame's identity doesn't match what was advertised. Try scanning again; if it keeps happening, something else on the network is answering for it." |
| Unknown certificate issuer | "FrameAlt doesn't recognise the key that signed this frame's certificate. This can happen with very new frames. You can allow it in Settings → Advanced, but only if you're sure this is your frame." |
| Frame doesn't support PACE v1 | "This frame uses a pairing method FrameAlt doesn't support yet." |

## 3. Home

Single screen, single frame. Revised 2026-09-23: Home shows only what is used every time,
and everything else sits one tap behind the frame's state.

**Not paired:** the app name and one button, `Connect your frame`. Nothing else. The
friend-code screen explains *Add friend* at the point where it matters.

**Paired: three elements, in this order.**

1. `Add photos`: the big primary button, opening the system photo picker.
2. `On the frame`: opens the Gallery.
3. **Frame state card:** only the frame's name and a status chip, **Ready** (green; a live
   Wi-Fi network and a cached endpoint) / **No Wi-Fi** / **Not reachable** / **Checking…**.
   Tapping it opens the **Frame screen**. Send progress is not repeated here: it is on the
   Frame screen and in the notification.

**Frame screen** (title: the frame's name), everything that is not everyday:

- **Name**, with an edit button. This is a label kept on this phone only: the frame's own
  name is set on the frame, and no known protocol message changes it. The label replaces
  the frame's name everywhere in the app. Clearing it goes back to the frame's own name,
  which Connection details always shows as "Name on the frame". Pairing a new frame clears
  it.
- **Status**: the chip, the reason underneath when it is not Ready, and `Check the
  connection`.
- **Activity**: current batch "Sending 12 of 50 — 3.2 MB of 14 MB" with a progress bar;
  waiting photos with `Send now`; each failed photo with its reason and `Retry` /
  `Remove`; recently completed batches, "50 photos sent · today 14:32".
- **Connection details**: placement, address, resolution, protocol version, last contact,
  permissions, and identity (IDs truncated), plus your name on the frame.
- `Diagnostics log`: the event log (§10 of the architecture).
- `Remove this frame`, behind its confirmation (§9).

**Status is never a lie.** "Ready" means we have a live Wi-Fi network and a cached
endpoint, not that a connection is currently open. If a send then fails, the card flips
to Not reachable, with the real reason on the Frame screen.

## 4. Review & Send

Reached from the picker *and* from the share sheet. Same composable, two entry points.

- Grid of selected photos with a per-item remove (`×`). Header: "12 photos to <frame
  name>".
- **Caption** — single optional text field applied to the whole batch. Per-photo
  captions are deliberately not in v1; note in the field's helper text: "Added to every
  photo in this batch."
- **Show the whole photo** — a switch, default **on**.
  - On: "The frame fits the whole photo on screen." (`scale = 1`)
  - Off: "The frame crops to fill the screen." (`scale = 2`)
- **Duplicate hint** — if a photo's content ID is already in `sent_ledger` for this
  frame: a small badge "Already sent" on the tile plus a one-line summary, "2 of these
  were sent before." Never blocks; the user may well want to re-send.
- `Send 12 photos` → prepares (progress: "Preparing 5 of 12…"), enqueues, then:
  - from the picker → Home, with the batch in Activity.
  - from the share sheet → finish the activity with a snackbar-style confirmation
    ("12 photos queued for <frame name>"), returning the user to the app they shared
    from.

Preparation failures are per-photo and never abort the batch:
> "3 photos couldn't be prepared and were skipped." with an expandable list of
> filename + reason.

## 5. Share-sheet entry

Intent filters for `ACTION_SEND` and `ACTION_SEND_MULTIPLE`, `image/*`.

- Paired → straight to Review & Send.
- Not paired → a compact screen: "Connect your frame first — FrameAlt needs to pair with
  your Frameo frame before it can send photos. [ Connect frame ]". The shared photos are
  held in the pending batch and appear in Review & Send once pairing succeeds.
- Non-image items in a multi-share are silently dropped, with a count: "4 of 6 items were
  photos; the rest were skipped."

**As built (Phase 4).** The share entry is its own activity, `ShareActivity`, launched into
the sharing app's task. Back and Send both finish it, so the user lands back in the app
they shared from; the confirmation is a toast, which outlives the activity. Single shares
are offered only for `image/*`. Multi-shares also accept `*/*`, the common type Android
reports for a mix such as photos plus a PDF. An item with no declared type is kept, and the
pipeline decides; if it is not an image, it fails with its own per-photo message. When
nothing shared is a photo, a short "Nothing to send" screen replaces Review.

## 6. Gallery ("On the frame")

Requires protocol ≥ 13 and the frame's *view photos* permission. Managing also needs
*manage photos*. FrameAlt asks for both in one request (kind 27, type 3), so the owner
approves once.

### 6.1 Access not yet granted

> ### See what's on your frame
> FrameAlt can show the photos on **<frame name>** and let you delete, hide or show
> them. The frame's owner has to allow this once, on the frame itself.
>
> [ Request access ]

After sending: "Waiting for approval — go to the frame and tap **Allow**." with a
spinner, a cancel button, and a 5-minute ceiling. On timeout: "No response from the
frame yet. You can leave this and try again later — the request stays pending on the
frame."

### 6.2 Granted

- Grid of 400 × 400 thumbnails fetched via kind 23, newest first by receive time.
- Each tile shows a video badge for type 1 and a greeting badge for type 2. Tapping a
  video or greeting opens the preview if the frame returns one, otherwise:
  "FrameAlt can only show photos for now."
- Header: "128 photos · 4 videos".
- Tap a photo → preview: full-size fetch, caption if present, capture date, received
  date. Actions: `Save to phone` (writes to `Pictures/FrameAlt` via MediaStore).
- **Managing** (D2, revised 2026-09-23). All of it is hidden when the frame has not granted
  *manage*; the grid then works read-only, with one line: "To delete or hide photos,
  allow management on the frame." and a `Request access` button.
  - Long-press a tile to start selecting; tap to add or remove. The top bar then shows
    "3 selected" with `Delete`, `Hide` and `Show`.
  - Overflow → **Select photos sent from this phone**: selects every item whose media ID
    this phone recorded when it sent it. It is the safe way to clear your own uploads,
    because it cannot touch what other people sent.
  - Delete confirms with a dialog that says what it costs: "Delete 12 photos from
    **<frame name>**? They'll be removed from the frame for everyone. This can't be
    undone." Buttons: `Cancel` / `Delete`. Delete is never one tap.
  - Hidden items (visible = false) show a "Hidden" badge; they stay on the frame but are
    left out of the slideshow.
  - Preview adds `Show on frame now` (kind 35), `Hide`/`Show`, and `Delete` (same
    dialog, for one photo).
  - Requests are split at 1000 IDs (the protocol's limit per message).

- Pull to refresh. Thumbnails cached in memory (bounded, ~64 MiB, mirroring the
  reference client) and not persisted to disk.

### 6.3 Protocol too old

> "This frame's software is too old for FrameAlt to list its photos. Sending still
> works."

## 7. Error copy map

Every failure the user can reach, and its exact words. Frame error codes from protocol
§7; transport errors from §3.

| Condition | Message | Action offered |
|---|---|---|
| No Wi-Fi | "You're not on Wi-Fi. FrameAlt sends photos over your home network." | Open Wi-Fi settings |
| On Wi-Fi, frame not found | "Can't reach **<frame name>**. It may be off, asleep, or on a different network." | Retry, Diagnostics |
| Connect timed out (targetSdk 37, permission denied) | "FrameAlt can't reach your frame without local network access." | Grant permission |
| Certificate issuer changed | "This frame's certificate changed. For safety FrameAlt won't connect. If you reset the frame, remove it here and pair again." | Remove frame |
| Identity differs from saved pairing | "The device at that address isn't your paired frame." | Rescan |
| Replayed / malformed record | "The connection to the frame was interrupted." | Retry |
| Frame code 1 *unauthorized* / 5 *permission required* | "The frame declined the request. You may need to pair again — open **Add friend** on the frame." | Re-pair |
| Frame code 9 *request declined* | "The request was declined on the frame." | — |
| Frame code 12 *frame limit reached* | "The frame is full. Delete some photos on the frame, then try again." | Retry |
| Frame code 6 *photo no longer exists* | "That photo is no longer on the frame." | Refresh |
| Frame code 3/4/2/0, or unknown | "The frame couldn't complete that. Try again in a moment." | Retry, Diagnostics |
| Receipt never arrived | "The frame didn't confirm the last photo. FrameAlt will try again." | — (automatic) |
| Photo too large / unreadable | "<filename> couldn't be prepared — it may be too large or in a format FrameAlt can't read." | Skip |
| Notifications denied | "Without notifications you won't see send progress when the app is closed. Sending still works." | Open settings, Dismiss |

Rules: name the frame, not "the device". Say what to do next. Never show a code, a hex
string, an exception class, or the word "error" on its own.

## 8. Notifications

One channel, `send_progress`, importance LOW (silent).

- While sending: "Sending to <frame name> — 12 of 50", indeterminate→determinate
  progress, a `Cancel` action.
- Waiting for Wi-Fi: "18 photos waiting for your home Wi-Fi." No sound; dismissible.
- Batch finished: "50 photos sent to <frame name>." Auto-cancel, taps to Home.
- Batch finished with failures: "48 sent, 2 failed." Taps to Home's Activity section.
- Never one notification per photo.

## 9. Settings

| Group | Items |
|---|---|
| Frame | Name (a label on this phone; see §3), Connection details, **Your name on the frame** (editable, ≤ 100 chars), Remove frame |
| Sending | Default for *Show the whole photo*, Photo quality (Standard 85 / High 92), Warn about duplicates |
| Advanced | Allow an unrecognised certificate issuer (off, with a warning dialog), Diagnostics, Log to a file (off) |
| About | Version, a plain-language note that FrameAlt is unaffiliated with Frameo and speaks the frame's local protocol directly |

**Connection details** mirrors the reference client: frame name, placement, address and
port, resolution, protocol version, permissions granted, peer ID (truncated with a copy
action), last contact.

**Remove frame** requires typed-out confirmation of what it costs: "Removing the frame
deletes FrameAlt's pairing. To send again you'll need a new friend code from the frame.
Photos already on the frame are not affected." Queued items for that frame are
cancelled.

## 10. Accessibility & layout

- Everything works at 200% font scale and in dark mode; no fixed-height text rows.
- Every icon-only control has a content description (`Remove <filename> from this
  batch`).
- The friend-code field uses `KeyboardType.NumberPassword`-style numeric input but shows
  its digits, with `autoCorrect = false`.
- Photo grids announce selection counts; tiles are at least 48 dp touch targets.
- Progress is text as well as a bar — screen readers should hear "Sending 12 of 50", not
  just a percentage.
